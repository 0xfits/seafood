**建议处置**：**裁定「收取」还是「销毁」二选一**。① 若「收取」⇒ 落 `uid = −1`（须 map 到 R101 白名单内的 kind，或新增 kind + 入白名单）；② 若「销毁」⇒ 走 `burn`，但 `$` 的 `burn` **仅平台可发起**（R25），且会改 `total_supply`、影响判据 4 —— **须一并裁定对账判据是否豁免**。

- `docs/data-layer.spec.md:534`（v0.17，DL81）：
  「**本册请求的 `kind` 扩展 = 0 个。** …⇒ **不得**因为「语义看起来更贴切」而新增 kind（R40：新增/删除 kind 必须走 migration 改 `ledger_kind_enum` **并**同步 `ledger.spec` §5.1…）」
- 账户模型：`ledger.spec:226` R9「`currency.total_supply` = 已铸总量…`supply_cap` = 供给上限，`NULL` 表示无限供给」；`:845` R101 平台账户白名单（`−1`/`−2`/`−3`）。**账户余额无 0–100 上限语义**，**无「溢出丢弃」语义**。
- 配对不变式：`ledger.spec:373` R41 / `:756` 判据 8：事件内 `Σ(delta + frozen_delta) == 0`（除 `mint`/`burn`）⇒ **账本不允许静默丢值**。

**冲突判定**

| 维度 | 需求 batt | 账本 | 相容？ |
|---|---|---|---|
| **kind 闭集** | 需「承接消耗 batt / 签到加 batt / 铸造清 batt / 分解加 batt」等 kind | **关闭集 20，无 batt**；`DL81` 明写「kind 扩展 = 0」 | ❌ 契约（须迁移，触 `R40`/`DL81`） |
| **单位 / 值域** | 单位 **%**，**0–100 且有上下限** | `account.balance` 是**整数余额（无 0–100 封顶）**；货币只有 `supply_cap` 上限 | ❌ 资金语义 |
| **账户白名单** | batt 归属「用户」 | `−1`/`−2`/`−3` 平台账户白名单**不含 batt** | ❌ 契约 |
| **溢出丢弃** | 「超出上限部分**直接丢弃**，不保留、不暂存」 | 事件配对不变式**禁止**凭空消失（`Σ=0`）；丢值 = 账实不符 | ❌ 资金语义（**与判据 8 直接冲突**） |
| **承接消耗 9 batt** | 承接任务 = **有资金腿** | 承接现为**无分录纯业务动作**（`data-layer.spec:507`） | ❌ 资金语义 |

**⇒ 结论**：batt **不能**直接落既有账本模型（kind 闭集 / 账户值域 / 配对不变式**三重不相容**）。同 `master-plan:1436` ⑤「**是**资金腿**（进 `ledger_entry`）还是**独立数据面**？」**—— **此问未决前不可实现**。

**建议处置**：需 Zang/Kevin 裁定 batt 的**账本身份**。三选一：(a) batt = `currency` 一行（`cid`）但须解决 0–100 封顶 + 溢出丢弃（账本无法表达）；(b) batt = **独立数据面**（不进 `ledger_entry`），仅业务表记账；(c) 新增 kind + 新账户语义（= 大改账本，须重开 `R40`/`DL81`）。

**⇒ 结论 = 直接冲突（契约）**：需求「角色文案后台可改实时生效」与现行「静态 locale 文件 + D16 后台不可改」是**相反机制**；且 `content_translation` 的口径 = **UGC**，**不能覆盖角色名称**（角色名是平台静态文案，非用户录入）。

**建议处置**：**须 Zang/Kevin 裁定**是否新开「后台可改的静态文案」机制（新 `app_config` 键 + 前端运行时读取 + 不做发版）。若采纳，须回答：① 与 D16「站点标题后台不可改」是否冲突（同族文案两种待遇）；② 「中/越」与既有「四语」如何并存（缺 en/hk 时回落？）；③ 是否需新 i18n 键 + 新路由 + 权限键（11 键内选）。
