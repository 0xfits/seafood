## 1. Kevin 逐字（唯一依据）

> 「商品卡片实际分为两个部分：image-container 和 content，后者分为四行：row1-wrap-title 内容是商品的标题，如果超出 48 个字符（24 个汉字）则截断，并在后面加'...'，尺寸 224x48；row2-wrap-service 内容放一些标签，目前暂时留空，尺寸 224x32；row3-wrap-price 内容是价格，形如：¥495 20人想要；row4-wrap-seller 内容是卖家信息，非常满意当前的状态，尺寸 224x48。」

## 2. 冻结口径（已向 Kevin 说明）

| 项 | 值 |
|---|---|
| 卡内宽 | **224** |
| 图片容器 `image-container` | **224 × 240**，`object-fit:cover` 居中裁切（图源链承 §26.1b） |
| 内容容器 `content` | **224 × 152** |
| `row1-wrap-title` | **224 × 48** · 单行 · 超 **48 显示宽单位**（汉字/全角 = 2、拉丁 = 1 ⇒ 24 汉字）截断 + 末尾**字面 `...`**（ASCII 三点；`…` 作废）· `...` 另计 ⇒ 最终 ≤ 51 单位 |
| `row2-wrap-service` | **224 × 32** · **当前留空**；高度恒在（空也占 32） |
| `row3-wrap-price` | **224 × 24** · `$` + 数字 + **一个半角空格** + `{{n}}人想要`（例 `$495 20人想要`）· 符号用站内 **`$`**（`¥` 判负） |
| `row4-wrap-seller` | **224 × 48** · 与 §26.1d/e **逐字不变**（24px 圆头像 + 掩码昵称 + 信用胶囊无图标） |
| **卡总高** | **392** = `240 + 48 + 32 + 24 + 48`（算术：240+48=288 → +32=320 → +24=344 → +48=392） |

### 2.1 412 作废（状态改写 · 旧句一字未删）

- 原契约（design v1.25 §26 `T122` / master §5.428 B / §5.429 A）= **412 = 图 240 + 中部 flex-1 124 + 卖家栏 48**。
- 新结构把中部 124 拆成三行定高 **48 + 32 + 24 = 104** ⇒ **392**，比原 412 **少 20px**（124 − 104 = 20）。
- 旧字面（§26.0 ① / §26.1a / §26.1c / §26.7 #1 / §5.428 / §5.429 / v1.25 版本头）**全部保留**；design §26.1 末与 §26.7 表末各插一行「已被 §26.11 取代」指针。
- **卡体不得再加 1px 实边框**：`240 + 152 = 392` 是内容盒分配；`box-sizing:border-box` + 1px 边框 ⇒ 内容盒 390 ⇒ 四行被压 2px。描边改 `inset box-shadow`。判负读数 = `getBoundingClientRect().height` 恒 **392**。

### 2.2 三条已定细节

1. **符号 = `$`**（Kevin 示例的 `¥` 为示意；承 master §2「符号只用一个 `$`」）。
2. **`wants` = `listing_favorite` 计数**：`COUNT(*) FROM public.listing_favorite WHERE listing_id = bID`（表 = 迁移 `0047`；取消收藏 = 物理 DELETE ⇒ 实时值）；**服务端算好下发、前端不本地算**。
3. **图片 240 优先**：若「保 412」与「保图 240」冲突，取图 240 ⇒ 卡高 392；保 412 需图 **260**（412 − 152）⇒ **待定**（`B42`）。

## 4. 判负（9 条 · 详表 = design §26.11.5）

1. 卡高 ≠ **392**（任意内容态：长标题 / 空标签 / 长价格 / 有图无图）。
2. 四行行高 ≠ **48 / 32 / 24 / 48**（逐行 `offsetHeight`）。
3. `image-container` 缺失 / 高 ≠ 240 / 非 `cover` 居中。
4. 标题超 **48 显示宽单位**未截断。
5. 已截断但末尾**非字面 `...`**（`…` / 无尾 / 双尾 / 空白尾）。
6. 价格行缺 **`$`**（出现 `¥` 亦判负）或缺「人想要」段。
7. `wants` 缺键 / 非整数 / 与 `listing_favorite` 计数不等（DB 单源逐行重算）。
8. `row2-wrap-service` 缺失（**即使留空也必须在场且高 32**）。
9. `row4-wrap-seller` 与 §26.1d 不一致（**卖家行「非常满意当前的状态」= 不变**）。

## 5. 边界 / 诚实披露

- **四行 = 封闭枚举（本版按逐字读法落）**：`content` 恰四行 ⇒ **描述行与剩余时间行不再在卡面渲染**；`rewardCard.timeLimited` 转**死键候选**（**不删**；`B42` 登记、`B40` 清理单届时复核）。要保留 = 一句话可改（从标题/标签行借高，卡高仍 392）。
- **`n = 0` 仍渲染「0人想要」**（Kevin 未给 0 的例外；隐藏 0 = 一句话可改，卡高不变）。
- **读口性能（登记、不裁）**：`listing_favorite` 现取索引 `UNIQUE(fav_uid, listing_id)` + `idx_listing_favorite_fav(fav_uid, time_created DESC, fav_id DESC)`，**无 `listing_id` 前导索引** ⇒ 计数应走聚合 `LEFT JOIN … GROUP BY listing_id`（单次分组扫描，实现单现取方案）或按行子查询；36 行/页可接受。上量后加 `(listing_id)` 索引或改 `LATERAL` 聚合 = **另立迁移单**。判负只盯数值正确，不锁 SQL 形态。
- **卡外宽不判负**：卡内宽 = 224（逐字）；卡外宽随 `T121` 六列网格派生（≈225 @1536，上轮实测卡内 223 = 1px 边框 ×2）。**252 / 225 均为测量近似**（承 §26.0）。
- **未做**：九条 AC 一条未跑；实现、i18n 键落地与 13 文件前推、探针取证均归并行实现 / 质检单。**本笔零代码**。
